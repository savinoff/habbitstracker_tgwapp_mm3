# Feature: История (history)

> **spec_version:** 0.1.0
> **status:** draft
> **last_updated:** 2026-07-30

## q1. Назначение

Просмотр прошлых записей. Цель — увидеть динамику без графиков и аналитики.

## q2. Точка входа

- В Mini App — нижняя вкладка «История» (см. `06-ui-states.md#q5`).
- Также доступна через `/history` команду в боте — открывает Mini App сразу на вкладке истории.

## q3. Фильтры периода

- `7 дней` (по умолчанию)
- `30 дней`
- `Всё`

Фильтр — сегментированный контрол вверху экрана. Состояние не персистится между сессиями (для простоты в v0.1.0).

## q4. Список дней

- Каждый день — карточка с датой (например, «Вт, 30 июля»).
- Внутри карточки — два блока: «Утро» и «Вечер».
- Каждый блок показывает:
  - иконку статуса: ✅ заполнено, ⏳ частично (пока не применимо), ❌ пропущено, — нет данных
  - компактное превью ключевых полей:
    - Утро: `сон Xч, настроение Y/5`
    - Вечер: `курил N, спорт: да/нет, настроение Y/5`
- Тап по карточке — раскрывает полные поля (q5).

## q5. Раскрытая карточка

- Утренняя запись: все 4 поля (`sleep_hours`, `sleep_quality`, `mood_morning`, `intention`).
- Вечерняя запись: все 6 полей.
- Кнопка «Редактировать» внизу — открывает форму (см. US-09).
- Если записи нет — кнопки нет, только надпись «Пропущено».

## q6. Пустые дни

- Если за день нет ни утренней, ни вечерней записи — день всё равно показывается со статусом ❌.
- Это сознательное решение, чтобы пользователь видел пропуски и не думал, что «система сломалась».

## q7. Производительность

- Запрос — `GET /api/history?days=7` (или 30, или all).
- Ответ — JSON-массив дней с полями `date`, `morning`, `evening` (или `null`).
- Без пагинации в v0.1.0: даже 365 дней — это < 100 КБ JSON.
