# Feature: Напоминания (reminders)

> **spec_version:** 0.1.0
> **status:** draft
> **last_updated:** 2026-07-30

## q1. Назначение

Бот в Telegram дважды в день шлёт пользователю напоминание заполнить опрос. Напоминания — основной механизм удержания привычки отвечать.

## q2. Расписание

| Слот | Окно (локальное время) | Дефолт | Допустимый диапазон |
|---|---|---|---|
| Утренний | 04:00 – 12:00 | 09:00 | любое `HH:MM` в окне |
| Вечерний | 18:00 – 23:59 | 21:00 | любое `HH:MM` в окне |

Пользователь может изменить время в настройках (см. `03-features/settings.md#q2`).

## q3. Логика отправки

- Бэкенд раз в минуту проверяет, кому из пользователей пора слать напоминание (cron-задача в Node, не системный cron).
- **Сравнение** делается в часовом поясе пользователя (см. `03-features/settings.md#q3`):
  ```
  now_user_local = now_utc + user.tz_offset_minutes
  if now_user_local.hour == settings.morning_hour and now_user_local.minute == 0:
      if no morning_survey for today_user_local:
          send_reminder('morning')
  ```
- **Сид-таблица `reminder_log`:** чтобы не слать дважды (если процесс рестартует в ту же минуту), факт отправки пишется в БД.

## q4. Тексты напоминаний

- Утро: «Доброе утро ☀️ Пора записать, как спал. Нажми кнопку ниже 👇»
- Вечер: «Привет 🌙 Как прошёл день? Запиши вечерний отчёт.»

К обеим — inline-кнопка «Открыть трекер» (Web App).

## q5. Догоняющее напоминание (только вечер)

- Через 60 минут после основного вечернего напоминания, если записи за сегодня нет — бот шлёт одно мягкое: «Не забудь про вечерний отчёт 🙂» (тоже с кнопкой).
- Больше напоминаний в этот день не шлём. Жёсткого давления нет (US-10).

## q6. Утренние догоняющие

Не отправляем. Если проспал — пользователь сам откроет Mini App в течение дня, либо увидит в истории пустой день.

## q7. Обработка смены часового пояса

- Если пользователь меняет TZ в настройках — все будущие напоминания считаются в новом TZ. Прошлые записи не пересчитываются.

## q8. Планировщик

- Реализация — in-process scheduler на `setInterval` с тиком 60 секунд, **не** внешний cron.
- При многократном запуске контейнера (Portainer redeploy) — должен сработать lock на уровне БД (SQLite `BEGIN IMMEDIATE`), чтобы две реплики не слали дубли. Для v0.1.0 ожидается один инстанс, но lock закладываем.
